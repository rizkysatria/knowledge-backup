# Source Analysis Rules

1. Current source / requirement / application behavior has precedence over generic assumptions.
2. Do not invent screens, UI elements, interactions, states, validations, business rules, limits, or implementation details.
3. Record unknowns explicitly when the source does not provide enough evidence.
4. Preserve source terminology and traceability.
5. Inventory relevant screens, sections, visible UI, interactive UI, states, navigation evidence, and alternate/error evidence.
6. Distinguish observed facts from interpretation.
7. If sources conflict, surface the conflict instead of silently resolving it.
8. Produce analysis in Markdown according to the analysis template/schema.
